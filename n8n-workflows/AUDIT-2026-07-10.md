## PART 2: Missing Workflows Entirely

These are needed but not created:

### 🔴 WF-REV-STRIPE-WEBHOOK (Critical)
**Trigger**: Stripe webhook (checkout completed, subscription updated, invoice failed)

**Purpose**: Handles client lifecycle events from Stripe

**Flow**:
```
Stripe webhook
  ↓ verify signature
  ↓ event type router
  ├─ checkout.session.completed → create Convex reviewClient row + Slack #wins
  ├─ customer.subscription.deleted → deactivate client, pause all workflows for them
  ├─ invoice.payment_failed → Slack alert, mark past_due
  └─ invoice.payment_succeeded → reactivate if was past_due
```

**Without this**: Manual client creation for every new signup.

### 🔴 WF-REV-GBP-COOLDOWN-CHECK (Critical)
**Trigger**: Daily 8AM

**Purpose**: Advance clients past GBP Manager 7-day cooldown

**Flow**:
```
Cron daily 8AM
  ↓
GET Convex /reviews/clients-with-expired-cooldown
  ↓
For each:
  → Update client.gbpApiActiveFrom = now
  → Slack notify: "✅ {client} GBP API now active — AI responses live"
  → Trigger backlog processing (any reviews from Days 1-7)
```

**Without this**: `gbpApiActiveFrom` field never updates, AI response workflow can't distinguish.

### 🔴 WF-REV-GUARANTEE-MILESTONE (Critical for retention/referrals)
**Trigger**: Cron every 6 hours (or Convex mutation trigger)

**Purpose**: When client hits 10 reviews since start → send referral ask, mark guarantee safe

**Flow**:
```
Cron every 6 hours
  ↓
GET Convex /reviews/clients-hitting-10-review-milestone
  ↓
For each:
  → Text owner referral ask: "🎉 You hit 10 reviews! Referral link: go.<domain>/refer/{clientId}"
  → Slack #wins: "🎉 {client} hit 10-review milestone, guarantee safe"
  → Update Convex: guaranteeMet=true, referralAskSentAt=now
  → If Founding 5 client: set foundingTestimonialDueAt = now + 60 days
```

**Without this**: Guarantee milestones invisible, referral flywheel never starts.

### 🔴 WF-REV-FOUNDING-CHECK (Critical for revenue collection)
**Trigger**: Weekly Monday 9AM (alongside WF-REV-05)

**Purpose**: Check Founding 5 clients approaching 60-day testimonial deadline

**Flow**:
```
Cron weekly
  ↓
GET Convex /reviews/founding-clients-approaching-deadline?daysRemaining=14
  ↓
For each:
  → Email Owner + Slack alert with days remaining
  → Text owner: "Hey {ownerFirstName}, quick reminder — your testimonial for the Founding 5 setup waiver is due in {daysRemaining} days. Book here: {calendly}"

GET Convex /reviews/founding-clients-past-deadline
  ↓
For each:
  → Charge $497 setup fee via Stripe
  → Update foundingTestimonialReceived=false, setupFeeBackBilled=true
  → Email client with receipt
```

**Without this**: $497 × 5 = $2,485 in setup fees never collected from lapsed Founding 5.

### 🔴 WF-REV-WARMUP (Critical for deliverability)
**Trigger**: Daily 7AM

**Purpose**: Enforce warmup ramp on new sender phones (Week 1: 50/day, Week 2: 200/day, Week 3: 500/day)

**Flow**:
```
Cron daily 7AM
  ↓
GET Convex /reviews/senders-in-warmup
  ↓
For each sender:
  → Compute today's cap based on days since activated
  → Set daily cap in workflow config (or Convex field)
  → When WF-REV-01/02 pull batches, respect cap
```

**Without this**: New sender phones might blast full volume Day 1 → carrier flagging → deliverability crash.

### 🟡 WF-REV-REACTIVATION-CSV-PARSER (Medium)
**Trigger**: Webhook (from onboarding form or manual CSV upload)

**Purpose**: Parse client CSV → insert into `reviewCustomers` batch

**Flow**:
```
Webhook (CSV URL + clientId)
  ↓
Download CSV
  ↓
Parse rows (firstName, phone, [jobCompletedAt])
  ↓
Validate + normalize phones (E.164)
  ↓
Bulk insert to Convex /reviews/customer-add-bulk
  ↓
Create reactivationBatch row
  ↓
Slack notify: "📥 {N} customers loaded for {clientName}"
```

**Without this**: Every client onboarding requires manual CSV upload via Owner's admin.
